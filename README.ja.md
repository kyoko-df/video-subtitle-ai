# 声幕 Shengmu — 動画・音声の AI 字幕ツール

[English](README.md) · [简体中文](README.zh-CN.md) · **日本語**

そのまま開発・実行できる Python プロジェクトです。FFmpeg で指定した音声トラックを抽出し、**ローカルの faster-whisper** または **OpenAI API** でタイムスタンプ付き字幕を生成します。ローカルブラウザー GUI と CLI を備え、両者は同じ処理パイプラインを共有します。

## 実装済み機能

- ffprobe で再生時間、音声トラック番号、言語、チャンネル数、開始オフセットを取得し、FFmpeg で 16 kHz モノラル PCM 音声を抽出します。
- ローカル Whisper モデルによる文字起こし。言語自動判定、CPU / NVIDIA CUDA、単語タイムスタンプ、認識プロンプト、無音フィルタに対応し、直近に使用したモデルを再利用します。
- 単語タイムスタンプから字幕を再分割し、句読点での区切りを優先します。中国語 / 日本語は 1 行 20 文字、その他の言語は 42 文字まで。1 字幕あたり最大 2 行・7 秒です。
- OpenAI `whisper-1` による文字起こしは単語・セグメント両方のタイムスタンプを要求します。長い音声は最大 600 秒ごとに分割し、境界の 5 秒前以内の無音区間を優先して切り、次のブロックへ前文をプロンプトとして引き継ぎます。
- **SRT、WebVTT、ASS、TXT、JSON** に出力します。TXT はプレーンテキスト、それ以外は時間情報を保持します。
- GUI はファイルのドラッグ＆ドロップ、一括文字起こし、タスク履歴 / 再試行 / ZIP ダウンロード、プロジェクトの永続化、自動下書き復元に対応します。
- プレビューと校正は、追加 / 分割 / 結合 / 削除 / 元に戻す / やり直し、検索置換、ループ再生、再生速度、全体オフセット、波形による位置合わせ、タイムラインのズーム、ドラッグでの時間調整に対応します。
- カスタムレイアウトルールと品質ヒント、字幕スタイル、二言語字幕、話者ラベル、単語ごとのハイライト、焼き込み動画 / 切替可能な字幕トラックの出力に対応します。
- オプションで OpenAI / ローカル LM Studio のテキスト翻訳と、ローカル pyannote による話者識別。モデルのダウンロード・進捗・管理・よく使う設定の保存に対応します。
- CLI は文字起こし、翻訳、ワンステップの二言語出力、音声トラック確認、JSON 形式変換、環境チェックに対応し、出力・入力ファイルの意図しない上書きを拒否します。
- 長時間動画の翻訳はバッチごとのチェックポイント、再開、限定リトライ、再帰的なバッチ分割、並列 1 / 2 に対応。ワークベンチではタイムアウト、出力上限、モデル対応の思考モードを設定できます。
- ASR は繰り返し抑制 / 小声向けのプリセットと高度な閾値を提供します。疑わしい繰り返しはまずマークし、試聴・一括削除・取り消しが可能です。
- GUI はループバックアドレスのみで待ち受けます。API キーはサーバーの環境変数から読み取られ、フロントエンドには渡されません。

## インストール

**Python 3.11 または 3.12** を推奨します。プロジェクトの対応範囲は Python 3.10 以降ですが、新しい Python ではローカルモデルの依存に対応するプラットフォーム向けパッケージが必要です。Windows、macOS、Linux で同じソースを使用します。

ローカルエンジンは PyAV の互換バージョンを固定しています。新しいバージョンで `metadata_errors` 引数が削除されて文字起こしが失敗するのを避けるため、プロジェクトで宣言した依存関係でインストールしてください。

最初に FFmpeg をインストールし、`ffmpeg` と `ffprobe` の両方がターミナルで実行できることを確認してください。

```bash
# macOS
brew install ffmpeg

# Debian / Ubuntu
sudo apt-get update
sudo apt-get install ffmpeg

# Windows PowerShell（インストール後にターミナルを開き直す）
winget install Gyan.FFmpeg
```

プロジェクトのディレクトリで Python 依存をインストールします。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[all]"
shengmu doctor
```

Windows の場合：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[all]"
shengmu doctor
```

片方のエンジンだけ使う場合は `[all]` を `[local]` または `[openai]` に変更します。基本依存は GUI サービス用のみで、AI 依存はオプションごとにインストールされます。

FFmpeg が PATH にない場合、`FFMPEG_BINARY` と `FFPROBE_BINARY` に実行ファイルの絶対パスを設定できます。`.env.example` は設定例であり、プロジェクトは `.env` を**自動読み込みしません**。

## GUI

```bash
shengmu gui
```

<http://127.0.0.1:8765> が自動で開きます。動画を選択 → 音声トラックと認識エンジンを選択 → 出力形式をチェック → 字幕を生成 → 校正 → 保存して出力 → ファイルをダウンロード、の順に操作します。GUI の表示言語は中国語で、以下のボタン名は実際の表示を引用しています。

動作確認にはまず `examples/local-demo.mp4` を Tiny モデルと英語で使えます。テスト用の合成音声動画で、同じディレクトリに実際のローカル認識で生成した SRT があります。

上記の手順でプロジェクトの `.venv` にインストール済みなら、macOS の `start-gui.command` または Windows の `start-gui.bat` をダブルクリックして起動できます。起動スクリプトは既定でモデルキャッシュをプロジェクトの `models` ディレクトリに置きます。`SHENGMU_MODEL_DIR` が設定済みの場合はその設定を保持します。

```bash
shengmu gui --port 9000 --no-browser
```

GUI は本機で動作するブラウザーアプリです。通常のアップロードは本機のプロジェクトディレクトリに保存され、接続済みの SMB / ローカル動画を直接読み取ることもできます。ローカルモードでは音声を AI サービスにアップロードしません。アップロードできるのは 1 ファイル 2 GB までです。それより大きい動画はパスを直接入力するか CLI を使ってください。モデルの初回ダウンロードにはネットワークが必要で、以降はオフラインで使えます。ブラウザーが動画のコーデックに非対応でも文字起こしは可能ですが、GUI 内では再生できません。

GUI は既定でプロジェクト、アップロード元ファイル、字幕、下書きをカレントディレクトリの `.shengmu/workspace` に保存するため、サービスを停止・再起動してもタスク一覧から校正を再開できます。`shengmu gui --workspace /path/to/projects` または `SHENGMU_WORKSPACE` で変更できます。同じプロジェクトディレクトリで起動できるサービスプロセスは 1 つだけです。処理中に中断したタスクは失敗としてマークされ、タスク一覧から再試行できます。

保持できるのは最大 30 個の元ファイル、100 個のタスクです。アップロード元ファイルの合計は 4 GB まで（アップロード中のファイルを含む）。処理中 / 待機中の文字起こしタスクは最大 5 個で、処理は直列実行します。ファイルを差し替えても旧プロジェクトは保持されます。「源文件缓存」（元ファイルキャッシュ）で不要な元ファイルを解放するか、古いタスクを削除してタスク枠を空けてください。永続化されたプロジェクトは自動で期限切れになりません。元ファイルを解放しても完成済み字幕は残りますが、再生・再試行・動画出力はできなくなります。字幕・動画・モデル・波形キャッシュは別途ディスク容量を使います。

### SMB / NAS 動画

「源文件 → 直接读取本地 / SMB 视频」（元ファイル → ローカル / SMB 動画を直接読み取り）に動画の完全なパスを入力し、「直接读取视频」（動画を直接読み取り）をクリックします。プログラムはパス参照のみを保存し、プレビュー、音声トラック抽出、動画出力は元ファイルを直接読みます。字幕・下書き・波形キャッシュ・出力動画は本機のプロジェクトディレクトリに保存します。元動画はアップロードキャッシュにコピーされないため、2 GB 単一ファイル / 4 GB アップロード容量の制限を受けませんが、30 個の元ファイル枠には数えます。一時音声の抽出と出力動画には本機の空き容量が必要です。

- **macOS**：まず Finder で ⌘K を押し、`smb://サーバー/共有名` に接続してログインし、マウント後のファイルパス（例：`/Volumes/共有名/動画.mp4`）を入力します。Finder でファイルを選択し ⌥⌘C でパスをコピーできます。接続方法は [Apple 公式の説明](https://support.apple.com/en-sg/guide/mac-help/mchlp1140/mac) を参照してください。
- **Windows**：まずエクスプローラーで共有に接続してログインし、`\\サーバー\共有名\動画.mp4` または割り当て済みドライブのパス（`Z:\動画.mp4` など）を入力します。本ツールを起動するのと同じシステムアカウントで共有に接続してください。割り当てドライブが他のアカウント / 管理者権限プロセスから見えないのを防ぐためです。パス形式は [Microsoft 公式の説明](https://learn.microsoft.com/dotnet/standard/io/file-path-formats) を参照してください。
- **Linux**：まずシステムで SMB 共有をマウントし、マウント先以下の完全なファイルパスを入力します。

アカウントとパスワードは OS が管理します。ツールは SMB 資格情報を受け取らず保存もせず、`smb://` アドレスへ直接接続もしません。共有が切断されても、生成済み字幕の校正とダウンロードは可能です。同じパスへ再接続すれば読み取りが再開します。元ファイルのサイズや更新時刻が変わると旧参照は読み取りを停止するので、動画を追加し直してトラック / 再生時間を更新してください。「移除视频引用」（動画参照を削除）は本機の参照と波形キャッシュのみを削除し、共有上・ローカルの元動画は削除しません。元ファイル一覧から既存の参照を開き直せます。

字幕編集：「新增」（追加）は再生位置以降の空き区間に字幕を挿入します。文字カーソルを字幕の途中に置いて「拆」（分割）をクリックすると、字幕内の現在再生時刻を優先し、それ以外では文字数比で時間を配分します。「并」（結合）は次の字幕と結合します。取り消しは直近 100 操作まで保持し、入力欄の外では Ctrl / Cmd + Z が使えます。時間やテキストの変更は関連する行とタイムラインブロックだけを更新し、再生位置の検索はキャッシュと二分探索を使います。

GUI で使用できるモデルは `tiny`、`base`、`small`、`medium`、`large-v3`、`turbo` のみです。任意のモデルディレクトリやリポジトリは CLI から指定してください。

### ワークベンチの機能

- **自動下書き**：編集後約 0.7 秒で下書きを保存し、切断に備えてブラウザーのローカルバックアップも保持します。更新や再起動後に下書きを復元します。「保存并导出」（保存して出力）を実行して初めてダウンロード用の字幕が更新されます。複数ページでの編集はバージョン番号で古いページの上書きを防ぎ、競合時はプロジェクトを開き直します。取り消し / やり直し履歴は現在のページ内にのみ保持されます。
- **一括処理と履歴**：「批量添加并转写」（一括追加して文字起こし）は現在の設定と各ファイルの先頭音声トラックを使います。キューが一杯のときは空きを待ち、「停止添加」（追加を停止）で以降のアップロードを止めても、待機中のタスクは継続します。タスク一覧から開き直し、キャンセル、再試行、削除ができます。ZIP には完了タスクの最後に保存された字幕が、タスクごとの独立したサブディレクトリで含まれます。
- **校正**：文字の検索置換は完全一致です。全体の時間オフセットは単語時刻も同時に動かし、範囲外になる場合は拒否します。現在の文のループ、0.5–2 倍再生、左右矢印での字幕切替、スペースでの再生が使えます。波形は選択した音声トラックに基づき、トラックオフセットを復元します。字幕ブロックをドラッグして全体を移動、両端をドラッグして境界を変更します。文字の変更・分割・境界調整は、有効でなくなった単語アライメントを消去し、文字の変更は対応する旧訳文も消去します。
- **レイアウトと品質チェック**：CJK / その他言語の 1 行の長さ、最大行数、最短 / 最長秒数、毎秒文字数を設定できます。品質チェックは原文と訳文について、長すぎ・短すぎ・読み速度超過・重複を指摘し、指摘をクリックすると該当箇所に移動します。再レイアウトは単語時刻による分割を維持します。再分割された字幕は訳文が消えるため、再翻訳が必要です。
- **スタイルと動画**：フォント、サイズ、色、位置、余白はプレビュー、ASS、焼き込みに使われます。出力内容は原文 / 訳文 / 二言語から選べ、話者名の表示も可能です。焼き込み動画は H.264 / AAC でエンコードします。字幕トラックのmuxは元の動画コーデックをコピーし、音声を AAC に変換、字幕は MP4 mov_text です。元動画のコーデックが MP4 に格納できない場合は FFmpeg のエラーが出るので、焼き込みに切り替えてください。どちらの方式も元メディアの全音声トラックを保持し、長時間動画の出力はキャンセルできます。
- **単語ごとのハイライト**：実際の単語タイムスタンプを保存し、アライメントがない場合は `estimated=true` マーク付きの推定時刻を使います。原文のプレビューと ASS / 焼き込みは単語ごとのハイライトに対応し、訳文に偽の単語アライメントは作りません。手動で文を変更するとハイライトは文全体に戻り、再認識で復元できます。
- **モデル**：各モデルの利用可否、ディスクサイズ、ダウンロード進捗を表示します。ダウンロードは公式 / 既知の CTranslate2 リポジトリの指定リビジョンから行い、再開できます。マネージャーは自分がダウンロードしたモデルを削除でき、既存の共有 Hugging Face キャッシュは「利用可能」と表示するだけなので、他のプログラムと共有するモデルを削除しません。使用中のローカルモデルは削除できません。よく使う設定を保存すると次回起動時に自動で読み込みます。

### 翻訳と自動話者識別

翻訳は **OpenAI API** と **LM Studio ローカル**に対応し、ワークベンチの「翻译方式」（翻訳方式）で選択します。どちらも字幕番号で結果を照合し、原文・時間・単語時刻・話者は変更しません。全バッチが成功した場合のみ訳文を更新し、失敗やキャンセルでは元の字幕と既存の訳文を保持します。訳文の手動入力・修正も可能です。

OpenAI 方式はサーバーにある `OPENAI_API_KEY` / `OPENAI_BASE_URL` を使い、Responses API の厳格な JSON Schema で出力します。既定のテキストモデルは `gpt-4o-mini` で、画面で変更できます。互換サービスは **Responses / Structured Outputs** に対応している必要があります。文字起こし互換のエンドポイントがあるだけでは翻訳に対応したことになりません。字幕テキストは設定したサービスへ送信され、API クォータを消費します。

LM Studio 方式では、まず以下の準備が必要です。

1. [LM Studio 公式サイト](https://lmstudio.ai/download)からアプリをインストールし、対象言語と構造化出力に対応する**テキスト会話モデル**をダウンロードして読み込みます。音声認識の Whisper モデルはここでのテキスト翻訳には使えません。
2. LM Studio の **Developer** ページで **Start server** を有効にします。既定ポートは `1234` で、モデルのコンテキストは最低 `8192` を推奨します。構造化出力への対応と実際の翻訳品質は選択したモデル次第です。[LM Studio 構造化出力ドキュメント](https://lmstudio.ai/docs/developer/openai-compat/structured-output)を参照してください。
3. ワークベンチで「LM Studio 本地」（LM Studio ローカル）を選択し、「刷新本地模型」（ローカルモデルを更新）をクリックして、モデル識別子を選択または入力し、対象言語を設定してから「翻译字幕」（字幕を翻訳）をクリックします。既知の埋め込みモデルは表示されません。読み込み状態とサービス能力を確認できます。よく使う設定を保存すると、翻訳方式・モデル・言語・翻訳設定を記憶します。

ローカル方式には `[openai]` 依存も OpenAI キーも不要です。既定アドレスは `http://127.0.0.1:1234/v1` で、`LM_STUDIO_BASE_URL` は本機 HTTP の `localhost`、`127.0.0.1`、`::1` のみを受け付けます。認証が必要なら `LM_STUDIO_API_KEY` を設定します（キーはブラウザーに返しません）。アプリは LM Studio のインストールやテキストモデルのダウンロードを代行しません。既存のモデルマネージャーは音声認識モデル用です。

モデル一覧は原生 v1 を優先し、旧バージョンでは v0 / 互換インターフェースにフォールバックします。思考が「モデル既定」の場合は `/v1/chat/completions` の厳格な JSON Schema を使い、明示的に思考を制御する場合はモデルが対応を宣言した原生 `/api/v1/chat` を使い、プロンプトで JSON を要求してから字幕番号を厳格に照合します。原生 API は JSON Schema パラメータを宣言していないため、このモードはプログラム側の検証に依存し、形式エラー時はバッチを分割します。[モデル能力](https://lmstudio.ai/docs/developer/rest/list)と[原生の思考設定](https://lmstudio.ai/docs/developer/rest/chat)を参照してください。

### 長時間動画の翻訳と再開

ワークベンチで「翻译设置与恢复」（翻訳設定と再開）を展開すると以下のパラメータを調整でき、CLI にも対応するオプションがあります。

| パラメータ             | 既定値                            | 範囲 / 用途                                                                 |
| ---------------------- | --------------------------------- | --------------------------------------------------------------------------- |
| 並列数                 | 1                                 | 1 / 2。サービスが容量不足を報告した場合は拒否、未報告の場合はサービス側で待機する可能性あり |
| バッチあたり字幕 / 文字数 | 8 / 2000                       | 1–40 / 100–12000。1 つの字幕は分割しない                                    |
| 一時障害のリトライ      | 2                                 | 0–3。認証・設定・タイムアウトの失敗は盲目的に再試行しない                      |
| タイムアウト           | ローカル 180 秒、OpenAI 120 秒     | 5–3600 秒。ローカルの既定値は `LM_STUDIO_TIMEOUT` で変更可能                 |
| 出力上限               | 4096 トークン                     | 128–32768。小さすぎると本文が切り詰められる可能性あり                        |
| モデルの思考           | モデル既定                        | サービスが対応を報告した選択肢のみ公開。旧バージョンは LM Studio 側で設定      |
| 再開                   | 有効                              | 現在の字幕 / 設定で未完了の部分のみを翻訳                                    |

各バッチは検証を通過した後に続行キャッシュを保存します。失敗やキャンセルでは正式な字幕を変更せず、保存済みの訳文は次回に再開できます。CLI は既定で、訳文チェックポイントとワンステップ処理の ASR キャッシュを OS のユーザーキャッシュ内 `shengmu/checkpoints` に保存するため、`--output-dir` を変えても続行でき、共有出力ディレクトリに `.translation-cache` を新設しません。`--checkpoint-dir <ディレクトリ>` または `SHENGMU_CHECKPOINT_DIR` でキャッシュ先を指定でき、コマンドライン指定が優先されます。ワークベンチは引き続き各プロジェクトディレクトリ内の `.translation-cache/` を使い、プロジェクトとともに削除されます。

アップグレード後に元の出力ディレクトリで初めて続行すると、そのディレクトリの旧 `.translation-cache` を読み取ってコピーし、元ファイルは保持します。その後は出力先を変更できます。旧キャッシュ位置を直接指定するには `--checkpoint-dir subtitles/.translation-cache` を使います。原文・時刻・対象言語・モデル識別子・思考モードを変更すると旧チェックポイントは隔離されます。同一識別子の背後にある重み / テンプレートを変えた場合は `--no-resume` で翻訳し直してください。タイムアウト、出力上限、バッチサイズ、リトライ、並列数は調整してから続行できます。キャッシュには字幕本文を含むため、該当キャッシュディレクトリを削除すれば消去できます。複数の CLI プロセスで同一チェックポイントに同時に書き込まないでください。

コンテキスト・切り詰め・形式エラーではバッチを半分に分割し、単条でも失敗する場合は番号を明示して報告します。進捗には完了字幕数、再開数、経過時間、リトライ / 分割回数が表示されます。キャンセルは処理中のリクエストの返却またはタイムアウトを待ってから新しいバッチの送信を止めます。並列 2 の実際の速度はモデル形式、サービスバージョン、メモリ、サービス設定に依存し、報告にある 2.1 倍の向上は保証されません。

「识别提示与质量选项」（認識プロンプトと品質オプション）で `standard`、`less-repetition`、`soft-speech` を選択でき、圧縮率・平均確率・無音声・VAD の各閾値を上書きできます。既定は `standard` のままで、プリセットを切り替えても無音声ハルシネーションが消えるとは限りません。後者の 2 つは試聴による確認が必要です。繰り返し抑制は低信頼度のセリフを取りこぼす可能性があり、小声向けはノイズ字幕が増える可能性があります。検出は診断スコアを保持し、字幕をまたぐ短い語 / 断片ループも調べます。長時間にわたる低文字速度はタイムライン上の疑義として個別にマークされ、推定の単語時刻は明示されます。通常の音の引き延ばしは単独では低文字速度の疑点になりません。検出はマークするだけで試聴の代わりにはなりません。品質チェックは位置を特定でき、マークした字幕の削除は取り消せます。JSON v2 にはオプションの `diagnostics` と `suspicions` が含まれ、旧 JSON も読み込めます。

`shengmu doctor` はネットワークなしで実際の焼き込みフィルタとエンコーダーを確認します。`shengmu doctor --network` はモデルダウンロードサービスと本機の LM Studio への疎通を追加で調べますが、モデルのダウンロードや推論は行いません。焼き込みには `ass` / `libx264` / `aac`、字幕トラックには `aac` / `mov_text` が必要で、`drawtext` には依存しません。能力が不足している場合、ワークベンチは該当する出力を無効化し、バックエンドも事前に拒否します。プログラムはエンジンを読み込む前に既定で `ORT_DISABLE_TELEMETRY=1` を設定し、既存ファイルを削除しません。

`shengmu doctor --output-dir <ディレクトリ>` は専用の一時ファイルで書き込み・置換・ハードリンク・排他的作成を調べ、終了時に削除します。ディレクトリがなければ作成します。文字起こし / 翻訳タスクの開始前にも出力ディレクトリを自動で事前確認します。SMB がハードリンク非対応の場合、上書きしない出力は排他的作成にフォールバックし、既存ファイルの上書きを依然として拒否します。コピーに失敗した場合は今回作成した未完成ファイルを片付けます。フォールバックの間、他のプログラムが一時的に未完成ファイルを読む可能性があり、置換プローブが成功してもネットワークストレージの永続性を保証するものではありません。翻訳コールバックは実際の進捗変化で送信され、待機中は 2 秒ごとに経過時間を更新します。CLI は重複除去と間引きを行い、完了およびリトライ / 分割の通知は保持します。

スクリプトからのポーリングは、**文字起こしは `job.status`、翻訳 / 焼き込み / 字幕muxは `job.operation.status`** を見てください。翻訳中も文字起こしの状態は `done` のままで、これで翻訳完了を判断できません。操作の終了状態は `done` / `error` / `cancelled` で、翻訳の詳細は `operation.stats` にあります。再起動後も中断された操作は設定と進捗を保持し、`error` / `interrupted=true` とマークされます。同じ設定で続行するとチェックポイントから復旧できます。

話者の自動識別は追加依存で、独立した Python 3.11 / 3.12 環境を推奨します。

```bash
python -m pip install -e ".[local,openai,diarization]"
export HF_TOKEN="あなたの Hugging Face トークン"
shengmu gui
```

初回利用時は [Community-1 モデルページ](https://huggingface.co/pyannote/speaker-diarization-community-1)で利用条件に同意し、その後プログラムがモデルをダウンロードして本機で推論します。本プロジェクトがあなたの代わりに条件に同意することはありません。`SHENGMU_DIARIZATION_MODEL=/path/to/community-1` を設定してオフラインのモデルディレクトリを使うこともできます。人数が分かっている場合は話者数を入力でき、プログラムは単語時刻と話者区間で字幕を分割します。名前は校正行で変更できます。エンジン未導入や権限未設定の場合は具体的なメッセージが出ます。通常の文字起こしと手動の話者ラベルは引き続き使えます。基本の `[all]` にはサイズの大きい pyannote / PyTorch は含まれません。

## CLI

### ローカルモデル

```bash
shengmu transcribe "video.mp4" --engine local --model small --language zh \
  --format srt vtt ass txt json --output-dir subtitles
```

本機での初回実行は `tiny` または `base` で流れを確認し、精度の必要に応じて `small` / `medium` / `large-v3` を選ぶのがおすすめです。ローカル文字起こしの速度とメモリはモデルとハードウェアに依存します。

```bash
# Mac / 汎用 CPU は既定で int8。CUDA や MPS は使わない
shengmu transcribe video.mp4 --model small --device cpu --compute-type int8

# NVIDIA GPU。互換の CUDA / cuDNN を別途構成する必要あり
shengmu transcribe video.mp4 --model large-v3 --device cuda --compute-type float16

# ダウンロード済みの faster-whisper / CTranslate2 モデルディレクトリを使う
shengmu transcribe video.mp4 --model /path/to/model
```

`SHENGMU_MODEL_DIR` でモデルキャッシュのディレクトリを指定できます。既定ではモデルライブラリ自身のキャッシュ位置を使います。

### OpenAI API

GUI または CLI を起動する**前**にキーを設定してください。

```bash
export OPENAI_API_KEY="自分の API キー"
shengmu transcribe video.mp4 --engine openai --language zh --format srt json
```

```powershell
$env:OPENAI_API_KEY="自分の API キー"
shengmu gui
```

API モードは字幕に必要な構造化タイムスタンプに対応する `whisper-1` で固定です。`--model` はローカルモデルのオプションで、API のモデルは変わりません。音声は設定した OpenAI サービスへ送信され、API クォータを消費します。

`OPENAI_BASE_URL` で互換サービスを利用できますが、サービスは `whisper-1`、`verbose_json`、`segments`、`timestamp_granularities` を実装している必要があります。互換ゲートウェイが提供する機能はサービス提供者次第です。

API リクエストは 120 秒のタイムアウトと最大 2 回のリトライがあります。音声は 16 kHz・モノラル・16 ビット WAV で分割し、1 ブロックあたり約 19.2 MB までです。`--chunk-seconds 30` から `600` で最大分割時間を調整できます。切り出し点の 5 秒前以内に少なくとも 0.3 秒の低音量区間を探し、無音の中央での分割を優先します。全サンプルを保持して完全なタイムラインを復元します。無音が見つからない場合は時間上限にフォールバックするため、連続発話の境界は校正が必要です。次のブロックのプロンプトには、ユーザーのプロンプトと前ブロックの末尾最大 400 文字が含まれます。単語タイムスタンプのない互換サービスではセグメント内の文字数比で時間を配分するため、実際の単語アライメントより精度が落ちます。

### 中国語と品質オプション

`--language zh` を明示し、独自プロンプトがない場合、既定のプロンプトは句読点付きの簡体字普通話を促します。言語自動判定時には中国語プロンプトを強制しません。これは認識のヒントであり、繁体字への強制変換ではないため、出力は校正が必要です。`--prompt` を設定すると既定のヒントを置き換えます。

ローカルエンジンは既定で `condition_on_previous_text=False` とし、長い音声での繰り返しを減らします。前文を使いたい場合は `--condition-on-previous-text` または GUI のチェックボックスを使います。既定では、既知のハルシネーションフレーズと完全に一致する孤立セグメントのみを除外します。例えば Amara.org のコミュニティ字幕や特定の「いいね・登録」系の締めです。これらの語を含む通常の会話は削除しません。録音に実際にこうした締めが含まれる場合は `--no-filter-hallucinations` または GUI のチェックを外して保持します。このフィルタは汎用のハルシネーション検出ではありません。

字幕の目標時間は約 1〜7 秒です。短い発話を無理に延ばして後続の発話を覆うことはしません。単語タイムスタンプの欠落・異常や極端に長い単語は比例配分で補いますが、単語ごとの精度は保証しません。

### マルチトラック・プロンプト・スクリプト

```bash
shengmu inspect video.mkv
# --track は ffprobe のストリーム番号で、音声トラックの通し番号ではない。映像ストリームも番号を消費する
shengmu transcribe video.mkv --track 2 --language zh --prompt "固有名詞, 専門用語" --format srt

# --quiet：結果の JSON を標準出力へ、エラーは標準エラーへ
shengmu transcribe video.mp4 --quiet --format srt json

# 既存の字幕を形式変換。AI は再呼び出ししない
shengmu export subtitles/video.json --format vtt ass --output-dir converted

# 既存の JSON を中国語へ翻訳。既定で二言語 SRT + JSON を出力
shengmu translate subtitles/video.json --target zh --provider lmstudio --model your-model
# 同じコマンドの再実行は既定で再開。タイムアウト / 並列数を調整して続行できる
shengmu translate subtitles/video.json --target zh --model your-model --timeout 600 --concurrency 2
# ワンステップ：文字起こし → 翻訳 → 二言語出力。翻訳失敗後の再実行は ASR を復旧する
shengmu transcribe video.mp4 --language ja --model medium --translate-to zh \
  --translation-model your-model --translation-timeout 600 --export-mode bilingual --format srt json
# 既存の訳文から再出力。モデルは呼び出さない
shengmu export subtitles/video.translated.json --export-mode bilingual --format srt

# 既存字幕の上書きを許可。入力ファイルの上書きは引き続き禁止
shengmu transcribe video.mp4 --format srt --overwrite
```

出力例：

```json
{ "segments": 42, "language": "zh", "files": ["/path/to/subtitles/video.srt"] }
```

コマンドは成功時に 0、入力 / 依存 / 文字起こしのエラーで 1、ユーザー中断で 130 を返します。`shengmu` の代わりに `python -m shengmu` も使えます。診断時は `--verbose`（サブコマンドの前後どちらでも可）を付けると、API キー / URL を伏字にした例外チェーンを出力します。GUI のバックエンド失敗も伏字化したスタックを記録し、フロントエンドにはスタックを返しません。

## 字幕データ形式

統一された `Transcript` / `Segment` は時間単位に**秒**を使います。JSON は保存して再変換でき、元動画や AI に依存しません。

```json
{
  "schema_version": 2,
  "source": "video.mp4",
  "duration": 10.0,
  "language": "zh",
  "engine": "local",
  "model": "small",
  "segments": [{ "start": 0.5, "end": 2.1, "text": "こんにちは、世界。" }],
  "metadata": { "audio_track": 1, "audio_offset": 0.0, "audio_duration": 10.0 }
}
```

SRT / VTT の精度はミリ秒、ASS は 1/100 秒です。JSON v2 は `words`（start / end / text / estimated）、`speaker`、`translation` を保持し、v1 の読み込みにも対応します。重複字幕は既定で拒否します。「允许重叠语音字幕」（重複音声字幕を許可）をオンにすると開始時刻順に並べた重複字幕を保存できますが、認識時の境界は既定どおり正規化されます。話者識別は発言者を区別するもので、同時発話の音源分離や覆われた会話の復元は行いません。SRT は `AT&T` のような元テキストを保持し、HTML エスケープしません。VTT はマークアップ文字をエスケープします。ASS のスタイル制御文字は全角に変換され、認識テキストがスタイル指示と誤認されるのを防ぎます。

## プロジェクト構成

```text
src/shengmu/
  media.py          ffprobe、FFmpeg、音声トラック、開始オフセット
  engines.py        ローカル / OpenAI エンジン、モデルキャッシュ、無音分割
  captions.py       単語レベルの字幕分割、折り返し、孤立ハルシネーションの除去
  diagnostics.py    環境チェックと伏字化した診断スタック
  models.py         統一字幕データと検証
  pipeline.py       2 つの入口で共有する処理フロー
  exporters.py      5 つの形式、一時書き込み、上書き保護
  cli.py            コマンドライン入口
  server.py         ローカル API、タスクキュー、編集、ダウンロード
  web/              フロントエンドビルド不要の GUI
tests/              形式、実 FFmpeg、API 契約、GUI インターフェースのテスト
examples/           サンプル JSON と SRT
```

新しい AI サービスを追加するには `Engine` プロトコルを実装し、`get_engine` に登録します。CLI と GUI は後続の処理を自動で再利用します。

テストは合成のマルチトラックメディアと模擬 API 応答を使い、ユーザーファイルのアップロードや有料 API の呼び出しは行いません。メディアテストには FFmpeg / ffprobe が必要です。OpenAI SDK 契約テストは SDK 未導入時にスキップされます。JavaScript の単体テストは Node.js 22 組み込みのテストランナーを使い、npm 依存やフロントエンドビルドは不要です。開発依存は新版 Starlette TestClient 用の httpx2 と、OpenAI SDK 契約テスト用の httpx の両方をインストールします。

GitHub Actions は Ubuntu、macOS、Windows × Python 3.10 / 3.12 で FFmpeg をインストールし、pytest / ruff / JavaScript テストを実行してリリースパッケージをビルドします。CI の設定は全プラットフォームでの実測完了を意味しません。

## 実用上の境界

- キャンセルは協調的です。FFmpeg は直接停止できますが、モデルの読み込み / 推論や送信済み API リクエストは現在の処理が戻るまで待つ必要があります。送信済みのクラウドリクエストは課金される場合があります。
- 単一ユーザーのローカルツールであり、公開マルチユーザーサービスには向きません。GUI はアトミック書き込みのローカルプロジェクト記録を使い、CLI の出力は指定ディレクトリに保存します。
- 音楽、訛り、複数人の重なった発話、ノイズの大きい音声では、字幕の精度と時間アライメントに人手の校正が必要です。
- 音声トラックの開始オフセットは動画タイムラインへ復元します。特殊なタイムスタンプの断続や破損したメディアは、先に通常の形式へ変換することを推奨します。
